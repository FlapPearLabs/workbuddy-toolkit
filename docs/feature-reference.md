# 功能参考

这份文档是 WorkBuddy Toolkit 的完整能力索引。README 保持简洁，这里负责说明：**有什么能力，以及什么时候该用。**

实现细节放在 [架构说明](architecture.md)、[工程笔记](engineering-notes.md)、架构决策记录（ADR）、详细规格和事故复盘中。

## 交互控制中心
 
### 终端图形化控制台 — `wb-tool`

基于 Steve Krug《Don't Make Me Think》与 Robin Williams《写给大家看的设计书》(CRAP) 原则打造的一站式交互入口。

- **适用场景**：日常高频维护、不希望记忆数十个 CLI 命令及选项开关的用户。
- **核心特点**：
  - 顶栏实时状态卡片：动态提取当前生效账号、健康状态、今日积分消耗及已存账号总数；
  - 面包屑级联回退：通过 `0` / `q` / `Esc` 阶梯式回退，末级配置返回父级菜单，仅顶级菜单退出；
  - 连续操作与会话审计：捕获底层命令的系统级退出代码，实现多步操作不打断终端流，退出时自动汇总输出会话执行审计报告。

## 账号管理

### 终端二维码登录 — `wb-login`

无需反复在桌面端退出、重新登录，就可以添加 WorkBuddy 账号。登录流程可以在终端显示二维码，并把登录后的账号状态保存为本地账号配置。

账号保存时会做冲突检查，降低新登录状态误覆盖其他已保存账号的风险。

### 账号清单 — `wb-list` / `wb-status`

查看已保存账号和当前活跃账号。状态工具会显示账号身份、凭据表示形式和健康状态，同时避免在普通输出中直接打印原始 access token / refresh token。

部分状态命令支持机器可读输出。若你要把它接入自动化，请先用当前版本的命令帮助确认字段。

### 账号删除 — `wb-remove`

把不再使用的本地账号备份移入 `auth_profiles/.trash/`，可随时恢复：

- `wb-remove <别名>` 删除（交互确认）
- `wb-remove -y -- -<别名>` 删除以 `-` 开头的别名
- `wb-remove --list-trash` 查看回收站
- `wb-remove --restore <文件名>` 恢复，自动还原删除前的别名
- `wb-remove --purge <文件名>` 单条销毁（不可恢复，清理残留占位）
- `wb-remove --empty-trash` 彻底销毁（不可恢复）

删除的是备份文件，不影响客户端当前登录。`-y/--yes` 只跳过普通确认；删除当前登录账号的备份属高危操作，仍需二次确认，只有 `--force` 才放宽该保护。

### 账号切换 — `wb-switch`

在已保存账号之间切换，不需要每次重新走完整登录流程。

切换前会先同步当前活跃账号的最新状态，避免 WorkBuddy 刚刷新出的新 Token 被旧账号配置覆盖。

### 凭据健康巡检 — `wb-audit`

检查已保存账号的凭据健康状态，并通过受支持的刷新路径处理临期或过期情况。巡检有节流机制，避免健康检查变成高频网络轮询。

在支持的平台上，当账号需要处理时可以触发桌面通知。

## 工作区与会话连续性

### 本地工作区 / 会话共享 — `workbuddy init`

切换账号后，历史会话看起来可能“消失”。根因是 WorkBuddy 会按当前账号身份过滤会话可见性。

Toolkit 初始化本地共享机制，复用 WorkBuddy 已有的共享会话语义，让多个本地账号继续看到同一份物理工作区和会话数据。

这个功能不会复制项目目录。

### 跨账号记忆汇总 — `workbuddy memory`

工作区共享解决“看得到同一份会话”，记忆汇总解决“每个账号都要重新教一遍规矩”。

做法不是拿 A 的副本盖掉 B，而是建一个**共享记忆库**：

1. `collect`：扫描所有账号的 `MEMORY.md`，把条目收进库；
2. 去重择优：相似条目聚成一簇，只让**质量更高**的一条参与后续注入，落选版本连同来源一起留档；
3. `apply`：把库里“这个账号还没有的”条目渲染到该账号 `MEMORY.md` 末尾的受管段落里。

四条不破坏承诺：

- **原文不改写**：渲染基线是账号文件**当前的自有内容**（首次接入时另存一份快照，只给 `restore` 用），
  渲染结果一律是“当前原文 + 追加段落”，原文逐字保留在文件开头；
- **不复活**：你在文件里删掉的行，下次 `apply` 不会写回来——只有 `restore` 才回到快照；
- **不删除**：账号自己新增的条目会被增量并入快照；被判定为低质量的版本进 `superseded`，不丢；
- **可还原**：`restore <账号>` 用快照写回，同时摘掉 SOUL / USER 里由分诊写入的受管段落，写回前自动备份当前文件。

质量分是**纯规则、可解释**的（长度、是否含具体数值/路径、是否有明确约束、模糊措辞、重复度），
同一份输入永远得到同一个分数——不用模型打分，避免“为什么这条被保留”无法复现。

相似判定只认**近重复**（≥0.90，且数字序列必须一致）：

- 只差标点、空格、语序的同一句话 → 合并；
- 数字不同（`30s` vs `60s`）→ 视为两条不同事实，不合并；
- 语义相近但措辞不同 → **不合并**。宁可漏合并，也不误删。

注入上限：客户端只读 `MEMORY.md` 前 4000 字。预算优先给账号自己的内容，
共享段落只在剩余空间里展开，放不下的条数会标注“另有 N 条未展开”，不会挤掉原文。
渲染按**最终拼出来的整篇长度**校验：原文自己就 ≥4000 字时连结尾换行都不补（否则写出 4001 字），
一条都塞不下时文件保持原样、不留空段落。共享段落自身还有一层预算，默认 800 字、最多 20 条，`apply --budget N` 可以临时收紧。

#### 索引与分片 — `workbuddy memory compact`

4000 字窗口装不下所有规则，`compact` 把原文留在磁盘、窗口里只放索引：

- 条目正文超过 `--shard-min`（默认 120 字）**或**本身是偏好/事实类（P3/P4）时建分片；
- 分片落在 `cache/shared_memory/shards/<id>.md`，首行记来源、首次收录时间与条目 id，空行之后是原文一字不改；
- `apply` 在正式条目之后、剩余预算内最多补 8 行索引（`- [P{n}] {摘要} → shards/<id>.md`，每行 ≤80 字）；
- **分片正文不会被注入**——它是存放处，不是通道。被冲突压制或含本机路径的条目也不进索引。

文件名只由条目 id 决定、内容没变就不重写，所以 `compact` 幂等；`collect` 会保留已有的 `shard` 与 `index_line`，先 `compact` 再 `apply` 不会把索引冲掉。

#### 发布口径 — 只发布规则，不发布事实

`apply` 不是把库里所有条目都搬过去。一条记忆先分级，默认只发布 P0–P2：

| 级别 | 判定线索 | 默认发布 |
|---|---|---|
| P0 红线 | 密钥 / 密码 / token / 凭证 / 隐私 / 客户信息 + 禁止类措辞 | 是 |
| P1 显式指令 | 必须、禁止、不要、一律、始终、只能、叫我、默认用 | 是 |
| P2 项目约定 | 提交、测试、分支、命名、流程、目录、合并、审查、部署 | 是 |
| P3 习惯 | 偏好、喜欢、倾向、语气、中文、回复风格 | 否 |
| P4 事实或推断 | 其余条目，以及含“可能 / 也许 / 大概 / 看情况”等模糊措辞的条目 | 否 |

另外，正文里出现本机绝对路径、URL、邮箱或 UUID 的条目一律不跨账号——这些是“某台机器上的事”，换个账号就失效。
以 `>`、`*`、`_`、`|` 开头的行（引用块、斜体元信息、表格行）也不跨账号：它们是 Markdown 的格式碎片，常常含“必须/不要”而骗过分级，单独搬走却谁也读不懂。
分级只决定能不能跨账号，不参与账号内择优：你自己文件里的事实不会被删。

判定顺序是：冲突压制 → 文档碎片 → 本机事实 → 级别 → 预算；同时命中多条时只记最先命中的那一类。

两个理由：客户端只有 4,000 字窗口，事实类条目又长又多，放行就会把别人的原文挤出上下文；
而项目路径、客户名、内部地址跨账号搬过去，只会让另一个账号在错误前提下行动。

想把偏好带过去，把它写成明确指令：`偏好简洁` 是 P3 不发布，`回复一律不超过 5 行` 是 P1 会发布。

#### 遗忘与冲突

- `forget <关键词或条目 id>`：把匹配条目移出共享库并留墓碑，下次 `collect` 不会复活（即使那段文字还在某个账号的 `MEMORY.md` 里）。
  默认只预览，`--apply` 才执行；账号原文一个字节都不动。墓碑存在 `library.json` 的 `tombstones` 里，目前没有解除命令。
- `conflicts`：先抹平肯定/否定再分桶，找出“只差一个否定词”的两条规则，只注入优先级更高的一条（级别 → 来源数 → 质量），
  另一条标 `suppressed` 留在库里备查、不注入、不删除。每次 `collect` 重算，工具不替你判断哪条才对，确认后用 `forget` 移除另一条。

`collect` / `compact` / `apply` / `rebalance` / `restore` / `forget` 全程持有跨进程锁（`cache/shared_memory/.hub.lock`，等待上限 5 秒），
进程内可重入，切号自动同步和手动命令撞车时不会互相覆盖。

#### 容量分诊 — `workbuddy memory rebalance`

4000 字只是 `MEMORY.md` 一个通道的上限。客户端实际有四个常驻通道：

| 通道 | 上限 | 适合放什么 |
|---|---|---|
| `MEMORY.md` | 4,000 | 事实、配置、项目状态 |
| `SOUL.md` | 10,000 | 行为准则、红线、流程 |
| `USER.md` | 10,000 | 称呼、语言、沟通偏好 |
| `IDENTITY.md` | 10,000 | 身份元数据（不放记忆） |

`rebalance` 按“关于人 / 怎么做 / 什么事”把超出的内容分流到 SOUL / USER，MEMORY 只留事实。

**默认按节迁移。** 文档里有 ≥2 个 `##` 标题时整节搬：标题、正文、缩进子项一起走，不会被拆成“父标题留在原地、子项搬去别处”。没有 ≥2 个二级标题的散条目文档，才退回逐行搬。去处分三种：标题含称呼/画像/偏好类关键词 → USER；标题含事实/状态/路径类关键词，或节内有两行以上本机路径 → 留在 MEMORY；其余方法论、准则、流程 → SOUL。

从最后一节往前搬，降到 `--target`（默认 3200）以下就停，所以留在 MEMORY 的前几节仍然读得通顺。CLI 逐节打印“留下 / 搬走”和字数，投影里的 SOUL / USER 数字已减掉上一轮写入的受管段落，重复跑不会出现假增长。

实测一个 5,953 字的真实记忆：MEMORY → 2,542 字，同账号 SOUL 1,792 → 5,253 字，内容一条没丢。

默认只打印计划，`--apply` 才写；写前对三个文件各做一次备份，迁移段用 `<!-- memory-rebalance:begin -->` 包裹，可重复执行（不会重复追加）。`restore` 会把这段一并摘掉，等于回到分诊前，不会在 MEMORY 和 SOUL 各存一份。

完整的发布分级、典型工作流、失效场景与回滚步骤见 [跨账号记忆共享](memory-sharing.md)。

## 日常自动化

### 签到与连续任务 — `wb-checkin`

对已保存账号执行支持的日常任务。

可以手动运行，也可以通过安装程序配置的平台原生调度器定时运行。

### 平台原生调度

支持：

- macOS：`launchd`
- Linux：`systemd --user`，必要时降级到 `cron`
- Windows：任务计划程序（`schtasks` 不可用时降级为登录启动项 `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\WorkBuddyDailyCheckin.vbs`）

后台调度不是必需项。你也可以完全手动使用 Toolkit。

## 使用量与模型工具

### 使用量 / 积分计量 — `wb-usage`

查看指定时间窗内的使用量和积分流速。详细计量规则见 [积分计量规格](spec-credit-metering.md)。

### 终端模型调用 — `wb-chat`

直接从终端调用 WorkBuddy 模型，不必每次打开完整桌面界面。

这是可选能力，与基础多账号管理相互独立。

### 模型清单 — `wb-models`

查看 Toolkit 能观察到的模型清单和相关元数据，辅助模型选择和成本判断。

### 容灾路由 — `wb-router`

可选的本地模型容灾层。它把“账号本身有效”和“这一次具体模型请求成功”区分开。

只有需要模型故障切换时才需要启用。普通账号切换和自动签到不依赖它。

## WorkBuddy 5.6+ 凭据兼容

较新的 WorkBuddy 版本开始把敏感本地凭据放进加密信封中。Toolkit 提供兼容层，不再依赖“Token 一定是明文字符串”的旧假设。

设计规则是：

> 运行时需要访问解密值，不代表要把它长期保存为明文。

兼容性取决于当前运行时，不能只看版本号。请运行：

```bash
workbuddy doctor
```

## 诊断能力

### 兼容性诊断 — `wb-doctor`

这是核心诊断命令，用于检查本地环境、凭据表示、WorkBuddy 运行时能力和部分旁路状态。

WorkBuddy 更新后，或行为突然变化时，优先先运行它。

### exit 137 / 命令卡死取证

针对进程被杀、资源耗尽或沙盒异常，项目提供专门取证入口：

```bash
wb-doctor --inspect-137
```

建议把结果与 [事故复盘](incidents/README.md) 一起看。

## 沙盒与运行时稳定性

### 日志保护 — `workbuddy-log-guard`

通过有界保留和容量限制控制沙盒 / 日志增长。实现会避免无脑删除仍被运行中进程持有的文件。

### 沙盒自愈 — `wb-sandbox`

处理已支持的沙盒 / 会话状态故障，并限制修复过程的范围。并发修复路径会做协调，避免多个进程同时改写同一状态。

### 临时文件与更新缓存清理

维护路径覆盖已知的异常临时日志，以及过期的 WorkBuddy 更新 / 迁移产物。它是定向治理，不是通用系统清理器：系统临时目录中的文件只有同时满足"日志类后缀、超过阈值、最近 15 分钟仍在增长、且仍被进程打开写入"时才会被原位截断，静止的大文件（数据集、压缩包、数据库、已结束的日志）一律不动。可通过 `clean_runaway_temp_logs: false` 或 `WB_CLEAN_RUNAWAY_TEMP_LOGS=0` 关闭。

### IPC 安全边界

Toolkit 的本地 IPC 集成采用有界等待和负载限制，避免异常旁路或运行时问题演变成无限终端卡死。

## 远端健康监控

仓库提供基于 GitHub Actions 的远端健康监控能力，可在受支持的远端 Runner 上执行健康检查，并利用 GitHub 工作流失败通知作为告警路径。

这是高级部署方式。本地用户不需要 GitHub Actions 也可以正常使用 Toolkit。

## 安全与回退

### 本地账号配置

已保存账号配置默认保留在当前机器上，除非用户主动把它们移动到其他位置。

### 敏感输出边界

状态 / JSON 输出路径应避免在普通输出中暴露原始 access token 和 refresh token。

### 进程与文件边界

运行时辅助程序在适用场景下使用更严格的文件 / 进程边界，降低凭据通过继承句柄、宽松权限或崩溃产物意外泄露的风险。

### 卸载 / 回退

Toolkit 的安装设计为可回退。需要退出时，使用对应平台的卸载路径移除命令链接、后台服务和 Toolkit 自己维护的集成状态。

## 上游兼容模型

实际可以分成三种情况：

1. **WorkBuddy 官方修复了原问题。** Toolkit 应该能够共存，或者该路径变得不再需要，同时不依赖修改应用包。
2. **WorkBuddy 更新了无关功能。** 只要依赖的本地契约没有变化，现有旁路行为应该继续工作。
3. **WorkBuddy 修改了关键路径、格式或协议。** Toolkit 应通过诊断明确暴露变化，而不是静默宣称兼容。

因此 `workbuddy doctor` 是日常工作流的一部分，不只是出故障时才用的命令。
