### 【第一幕：核弹级死锁——1.7 万行规则雪崩，CPU 狂转 64 分钟】
*(画面：展示 Terminal 执行简单命令卡死 120 秒报 exit 137 的报错截图，随后切出 `sample` 堆栈)*

大家用 AI 编程助手时，是不是经常遇到终端命令莫名其妙卡死？跑一个简单的脚本，转圈两分钟，直接超时报错退出？

今天下午，我在 macOS 上跑自动化任务，WorkBuddy 的终端又彻底瘫了。任何终端命令直接假死，等满 120 秒被前端当场 SIGKILL 强杀！

很多普通用户可能重启一下就算了，但我有工程洁癖，我必须看看它底层到底在搞什么鬼。我挂载系统探针，用 macOS 原生 `sample` 对死锁进程进行物理采样——

好家伙！一个叫 `sandbox-center` 的沙盒核心守护进程，单核 CPU **占满 100%，持续死锁狂转了整整 64 分钟**！

堆栈清晰地指着 Rust 函数：
`compile_sbpl_clauses -> shadowed_verdicts::dim_covered`

我顺藤摸瓜逆向解包它的沙盒规则文件 `tsbx_rules.json`，看到代码那一刻我整个人都气笑了：
**腾讯的大厂架构师们，在配置沙盒临时文件白名单时，只写了 Windows 的 Temp 通配符，居然把 macOS 的全局临时目录 `$TMPDIR` 给完完全全漏掉了！**

这就意味着，在苹果电脑上，你只要在终端里让工具碰一下临时目录，沙盒中心就因为没有规则，疯狂向后台守护进程动态注册单条绝对路径规则。跑上几天，规则生生堆积了 **17,500 多条**！

更炸裂的还在后头：
这个所谓的底层沙盒编译器，在把规则编译成苹果系统的 Seatbelt 沙盒语法时，判定规则重复的算法，居然写成了一个极其低级的小学奥数级双重循环——$O(N^2)$ 线性扫描！

数学稍微过关的都算得出来：
1.7 万条规则做二次方比较，**整整一亿五千三百万次比对**！直接把底层的事件调度线程彻底打死！后续所有命令等 3 秒超时丢弃，前端等 120 秒无情报错！

还没完！我继续抓它的 `sandbox-cli`，发现这帮大厂“技术大牛”，在命令执行完清理 PTY 终端线程时，居然写死了 `sleep 5000ms`！哪怕命令 1 毫秒跑完，也要先干等 5 秒假死才能关管道！而且关掉主界面，这帮守护进程居然不自杀，变成孤儿僵尸进程在后台继续 100% 烧你电脑的电！

**这就是所谓的腾讯拳头产品？跑通就完事，根本没有代码审查，甚至连最基础的操作系统机理与算法复杂度常识都没有！**

### 【第二幕：细数四大“草台班子”生产事故，大厂工程师的遮羞布】
*(画面：快节奏字幕弹出四大事故，配红章批注)*

这已经不是我第一次给腾讯 WorkBuddy 擦屁股了。在这之前，我们已经连续抓获并修复了三大生产级事故：

#### 1. 沙盒日志无限暴走，吃光 15GB 磁盘
WorkBuddy 偷偷在后台狂写终端 PTY 日志，只管写不管删，几天之内吃掉用户十几 GB 磁盘。更离谱的是，`.workbuddy/workspace/sessions` 里面堆积了 **32 万个快照文件**，把用户电脑的文件系统活活卡瘫！

#### 2. Cargo 编译多个 Agent，明明有缓存复用机制却各编译各的
官方吹得天花乱坠的“多智能体协作”，在底层跑 Rust 构建时，让每个子 Agent 在各自的独立沙盒里从零拉代码、从零重新编译几十上百个 crates！明明业界二十年前就有 `sccache` 这种共享编译缓存的最佳实践，他们就是不用！风扇狂转、CPU 跑满、磁盘瞬间被多个 `target` 吃掉几十个 G，纯纯的资源浪费！

#### 3. 最恐怖的死罪：Git 工作区代码莫名蒸发！
这一点最令程序员无法容忍！
在特定场景下，用户在终端执行正规的 `npm ci`，WorkBuddy 搞的一个所谓的“防误删”Node 垫片（`genie-safe-delete.cjs`），居然粗暴硬编码“只要单次删除超过 20 个文件就报错抛异常”，直接导致包管理器崩溃并留下脏状态；
更致命的是，其底层沙盒过滤层在特定竞争态下，**直接把用户 Git 工作树里的代码文件删掉了 59 个！**
代码凭空丢失，这是做开发工具最不可饶恕的底线问题！我把完整的复现工程和不可伪造的取证链打包成了公开开源仓库 `workbuddy-safedelete-rootcause`，直接提交给了腾讯的研发团队，至今他们都未能给出原生自愈方案。

### 【第三幕：二本文科生，用开源工具教大厂做软件】
*(画面：切到 `workbuddy-toolkit` 终端操作画面：绿色的 OK、毫秒级响应、清爽的架构)*

面对这堆让人啼笑皆非的底层漏洞，我们没有选择忍气吞声，而是把所有修复手段全部开源封装成了一个工具箱——**`workbuddy-toolkit`**。

- 他们漏配临时目录导致死锁？我们写了个 `wb-sandbox heal`，直接走底层 Unix Socket IPC 动态注入通配规则，秒级将 1.7 万条规则降到 48 条，编译耗时从 64 分钟降到 0.2 毫秒；
- 他们的快照堆积吃磁盘？我们实现 `wb-sandbox clean`，`lsof` 句柄感知，只做外科手术式精准修剪，绝不伤用户一份代码；
- 他们切账号非要微信反复扫码、工作区隔离折叠？我们直接逆向 SQLite 注入触发器，实现全域工作区打通、秒级无缝切号与容灾路由！

现在，这套工具已经迭代到了 `v0.6.0`，在 GitHub 完全开源，拥有 100% 通过率的 74 个自动化全平台测试用例，零第三方依赖，纯本地原生运行。
